# Crant Peek 官网

目标域名：**https://crantpeek.eno.ink**。纯静态 HTML、CSS、JavaScript，nginx 直接托管，无需 Node.js、数据库或常驻后端。字体、视频和图标保存在本机，没有外部样式 CDN。

## 自动下载源

访问首页时，浏览器调用 GitCode 官方公开接口：

```text
https://api.gitcode.com/api/v5/repos/CrantAI/CrantPeek/releases/latest?type=latest
```

页面从最新正式 Release 的 assets 中选择固定名称的三个程序包，使用该附件的 browser_download_url，不再指向网站本地包或 GitHub 下载地址：

- Crant-Peek-macOS.zip
- Crant-Peek-Windows.zip
- Crant-Peek-Windows-Setup.exe

GitCode 当前接口允许官网 Origin 的跨域读取。浏览器不携带账户凭据或 Token，版本信息不写入 localStorage，避免保存过期签名链接。未来发布时保持上述文件名，镜像同步后访问首页即可取得最新版，不需重新修改或部署网页。

若没有正式版、附件未同步、接口故障或网络不可用，页面明确显示状态，对应下载按钮保持不可用，不会把源码 Tag 归档冒充程序，也不会跳回 GitHub。若 GitCode 将来更改公开 API 或跨域策略，需要相应调整；不能将个人 Token 填入公开 JavaScript。配置严格 CSP 的外层代理时，需要允许连接 https://api.gitcode.com。

本地遗留的 public/downloads/ 和 prepare-downloads.py 可用于已有链接的兼容备用，页面不再使用它们。仅部署新版官网不需要这些二进制文件；原有 nginx /downloads/ 配置可以保留，避免已有下载链接失效。

## 部署

将域名 DNS 指向服务器。上传完整 public/ 及 nginx.conf，例如存放于 /tmp/crantpeek-website：

```sh
sudo mkdir -p /var/www/crantpeek/public
sudo cp -R /tmp/crantpeek-website/public/. /var/www/crantpeek/public/
sudo find /var/www/crantpeek/public -type d -exec chmod 755 {} \;
sudo find /var/www/crantpeek/public -type f -exec chmod 644 {} \;
sudo cp /tmp/crantpeek-website/nginx.conf /etc/nginx/conf.d/crantpeek.conf
sudo nginx -t
sudo systemctl reload nginx
```

nginx 全局 http 配置需要加载系统 mime.types，确保 video/mp4、字体及 JavaScript 类型正确。静态资源缓存一小时，首页不缓存；部署新版代码后，可刷新浏览器缓存。

示例配置先提供 HTTP。已有 HTTPS 反向代理可将上游指向此站点。如果由这台 nginx 提供 HTTPS，安装对应系统的 Certbot 与 nginx 插件后执行：

```sh
sudo certbot --nginx -d crantpeek.eno.ink
sudo certbot renew --dry-run
```

需要先让 DNS 生效并开放 80、443 端口。上传文件本身不会自动获得 HTTPS。

## 检查与发布

1. 确认首页显示最新正式版本号。
2. 检查 macOS、Windows 便携版和安装包按钮都使用 GitCode 实际附件地址，不是源码归档。
3. 检查三个包下载后与 Release 校验值一致，验证视频播放与拖动进度。
4. 镜像同步前或接口请求失败时，应出现明确提示，对应下载按钮不可用。

```sh
curl -I https://crantpeek.eno.ink/
curl -I -H 'Range: bytes=0-1023' https://crantpeek.eno.ink/assets/demo.mp4
node --test website/releases.test.cjs
```

GitHub 仓库已配置正式发布流程：应用版本与 vX.Y.Z tag 相符、双端检查和构建成功后，tag 工作流核验并一起上传三个程序包与校验文件，创建非预发布 Release。代码镜像只同步 Git 数据和 tags，不会生成发行版和程序附件。下载源使用单独的自动同步流程，配置方法如下。

官网保留平台架构、签名、公证、Windows 实机验收及图片理解未实现等说明。正式 Release 不代表已完成这些项目。

Noto Serif 字体采用 SIL Open Font License，许可证在 public/assets/，源码采用 MIT 许可。

参考：[GitCode 最新 Release 接口](https://docs.gitcode.com/docs/apis/get-api-v-5-repos-owner-repo-releases-latest/)、[nginx 静态文件](https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files)、[Certbot nginx 配置](https://certbot.eff.org/instructions?ws=nginx&os=pip)。


## 下载源附件同步（仅部署配置，不在产品界面宣传）

1. 在下载源账户中创建有 `CrantAI/CrantPeek` 仓库 Release 写权限的访问令牌。
2. 在 GitHub 仓库 Settings → Secrets and variables → Actions 中新增加密 Secret `GITCODE_TOKEN`。令牌不能提交到仓库、网页或聊天中。
3. Actions → **Sync download source** → Run workflow，输入 `v0.1.0`，补同步已经发布的正式版。
4. 后续正式版发布时自动同步，无需修改网站版本号。CI 创建的 Release 通过复用工作流显式同步；人工发布的正式版通过 published 事件同步。

脚本下载三个完整程序包和 SHA256SUMS，先核对原始校验值，再创建暂不可被官网采用的待同步版本，上传文件并重新下载逐个核对 SHA-256，全部正确后才标为最新正式版。同版本重跑会校验已有文件并补传缺失文件，已有文件不一致时停止，不覆盖原附件；补同步旧版不会覆盖更新的正式版。

缺少令牌时同步会明确失败，但已经发布的 GitHub 正式版会保留。代码镜像尚未同步目标 commit/tag 时，创建下载源发行版也可能失败，应等待镜像完成后重跑。接口契约已按官方文档编写，取得实际令牌后仍需执行一次端到端验证。

参考：[创建发行版](https://docs.gitcode.com/docs/apis/post-api-v-5-repos-owner-repo-releases/)、[附件上传地址与 PUT 请求](https://docs.gitcode.com/docs/apis/get-api-v-5-repos-owner-repo-releases-tag-upload-url/)。
