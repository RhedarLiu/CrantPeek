# Interface localization and design

## Localization contract

Application-owned visible copy lives in Fluent resources:

- `crates/peek-runtime/locales/en.ftl`
- `crates/peek-runtime/locales/zh-CN.ftl`

Use stable message IDs rather than Chinese/English strings or concatenated sentence fragments. Dynamic content uses Fluent named parameters. UI widget IDs are stable and independent of translated labels. Interface language is independent of the translation target language.

Supported selections: system, Simplified Chinese, English. Unsupported system locales fall back to English. Saved language changes update widgets and tray menu in place. Asynchronous requests carry their own concurrent Fluent bundle rather than depending on worker-thread local state.

Core config validation and network response errors return stable codes. UI translates codes. Raw OS/library diagnostics remain technical details under a localized error wrapper; user content, dictionary definitions, model output, protocol identifiers, paths and API model IDs are not translated as interface labels. Internal model instructions are not interface strings. Platform keycap names (⌘, Ctrl) are platform constants passed as message parameters, not translatable prose.

Any user-visible string literal added to application source without a resource key is a defect. `cargo test -p peek-runtime i18n` verifies that resource references exist, but reviewers must still check newly added literals.

### Verification

`cargo test -p peek-runtime i18n` checks catalog key parity, interpolation parameter parity, resource references, fallback, and asynchronous language behavior. The reference audit scans `peek-gpui/src/main.rs` and `snip.rs`; a new view module must be added to its source list, and stable widget IDs belong in its allow list rather than in the catalogs. New languages must provide the same keys and parameters. Fixed Chinese UI literals are prohibited in application Rust source; tests may assert fixture text.

## Native visual direction

No Tailwind, CSS, browser or WebView dependency. GPUI recreates the visual principles of the supplied references:

- Monochrome light/dark surfaces with fine gray borders.
- Rounded input/result cards and pill-shaped primary actions.
- Consistent typography, whitespace and icon actions with localized tooltips.
- Scrollable settings content with fixed save/cancel footer.
- Stable state IDs when switching language.

## Isolated visual previews

These render only the app's own framebuffer. They do not capture the desktop, load user configuration, register tray/hotkeys or call models.

```sh
cargo build -p peek-gpui
PEEK_RENDER=previews/en.png PEEK_LANGUAGE=en ./target/debug/peek-gpui
PEEK_RENDER=previews/settings-zh-cn.png PEEK_LANGUAGE=zh-CN PEEK_PAGE=settings ./target/debug/peek-gpui
PEEK_RENDER=previews/serif.png PEEK_FONT_SET=serif ./target/debug/peek-gpui
```

`PEEK_LANGUAGE` forces a catalog for a preview; without it the interface follows the system locale. `PEEK_FONT_SET` selects the bundled font set. Windows: set these environment variables in PowerShell and run the debug executable. macOS previews do not substitute for Windows native interaction tests. Preview rendering exits automatically after saving one PNG.
